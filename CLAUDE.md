# AGENTS.md — правила проекта для ИИ-агентов и людей

Этот файл читают Codex, Claude и все участники команды. Перед любой задачей прочитай его целиком,
затем `docs/contracts.md`. Копия файла лежит в `CLAUDE.md` — держите их одинаковыми.

## О проекте

**ИИ-аудитор безопасности документов для тендерного специалиста** (хакатон B2B-РТС «AI Procurement Copilot», задача 7).

Пользователь загружает документ закупки (.pdf, .docx, .xlsx) или вводит текстовый запрос.
Система:
1. извлекает текст с привязкой к страницам и разделам;
2. находит персональные данные (152-ФЗ), коммерческую тайну и финансовые данные;
3. **маскирует найденные ПДн до отправки текста в LLM** (ключевая идея проекта);
4. проверяет чек-лист из трёх категорий: согласования, грифы конфиденциальности, сроки хранения;
5. применяет настраиваемые правила (152-ФЗ, 187-ФЗ, GDPR, 98-ФЗ, внутренние политики);
6. выдаёт отчёт: нарушения с цитатами и ссылками на статьи, светофор (red / yellow / green), рекомендации.

Критерии приёмки, которые мы обязаны закрыть:
- выявление ≥ 90% ПДн, ≥ 85% коммерческой тайны;
- чек-лист из 3 категорий; ссылка на пункт регламента у каждого нарушения; светофор;
- файл 50+ страниц без ошибки 504 (вся обработка — в очереди Celery);
- интерфейс понятен юристу без инструкций;
- запуск одной командой `docker-compose up --build`.

## Жёсткие правила

1. **Контракты неприкосновенны.** Схемы в `docs/contracts.md` и `backend/app/schemas/` меняет только тимлид. Если контракт мешает — напиши в PR, не меняй сам.
2. **Никаких реальных персональных данных в репозитории.** Репозиторий публичный. Только синтетика (Faker) и открытые документы без ПДн физлиц.
3. **Никаких секретов.** API-ключи только в `.env`, который в `.gitignore`. В код и примеры — заглушки.
4. **ПДн не попадают в логи.** Логируем id документа, этап, время, количество найденных сущностей — но не сами значения.
5. **В LLM уходит только замаскированный текст** (`[PERSON_1]`, `[SNILS_1]` …). Прямой вызов LLM с исходным текстом — ошибка.
6. **Тяжёлая работа — только в Celery.** HTTP-эндпоинт возвращает `task_id` за < 1 секунды.
7. **Режим `LLM_PROVIDER=mock` должен работать всегда:** приложение и тесты запускаются без API-ключа.
8. **Каждая новая функция — с тестом.** Минимум один тест на «хороший» случай и один на граничный.

## Стиль кода

- Python: аннотации типов везде, функции до ~40 строк, понятные имена на английском, комментарии и docstring можно на русском.
- Никаких `print` — модуль `logging`.
- TS: строгий режим, без `any`; типы API лежат в `frontend/src/api/types.ts` и повторяют контракты.
- Весь текст интерфейса — на русском, без технических терминов («Найдены персональные данные», а не «PII entities detected»).

## Git и задачи

- Каждая задача имеет номер `T-XXX`. Ветка: `feat/T-012-short-name` или `fix/T-020-short-name`.
- В `main` напрямую не пушим. Только PR, ревью — тимлид.
- Описание PR: что сделано, как проверить (команда), что не сделано или вызывает сомнения.
- `main` всегда должен собираться и запускаться через `docker-compose up --build`.
- Маленькие PR лучше больших: один PR — одна задача.

## Как агенту выполнять задачу

1. Прочитай этот файл, `docs/contracts.md` и текст задачи.
2. Работай только в файлах и папках, указанных в задаче.
3. Если нужная функция другого модуля ещё не готова — используй заглушку по контракту, не пиши её сам.
4. Напиши код и тесты, запусти тесты.
5. Подготовь описание PR по шаблону выше.
