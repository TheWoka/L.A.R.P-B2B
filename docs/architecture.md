# Архитектура «Грифа»

«Гриф» проверяет документы закупок в очереди Celery. FastAPI принимает файл или
текстовый запрос и возвращает идентификатор задачи; браузер получает результат
отдельно. Комплект связывает до 20 документов со сводным отчётом. Сканы распознаются
локально Tesseract, режим генеративной нейросети выбирается для каждой проверки.
Схемы данных и API определены в [contracts.md](contracts.md), контракт v3.

## Компоненты и конвейер

```mermaid

    X --> P["ПДн: регулярки с контрольными суммами, Natasha NER, словари"]
    P --> K["Маркеры чек-листа: согласования, грифы, сроки хранения"]
    K --> M["Маскирование найденных ПДн: [PERSON_1]"]
    M --> C["Классификатор grif-cls: КТ и особые категории, повторная маска"]
    C --> Q{"LLM включена?"}
    Q -->|да| S["Особые категории ПДн: только маскированный текст"]
    S --> N["Повторная маска новых ПДн"]
    N --> T["Коммерческая тайна: только маскированный текст"]

    G --> U["Удаление исходника"]

    U --> H["Хранение отчёта и копии: REPORT_TTL_DAYS; периодическая очистка Celery"]
    W --> D
    S -.-> O["Ollama: профиль local-llm, CPU / GPU"]
    T -.-> O
    E -.-> O
    S -.-> V["Облачный OpenAI-совместимый API"]
    T -.-> V
    E -.-> V
```

Сплошные стрелки показывают обработку и сохранение, пунктирные — необязательные
вызовы выбранного провайдера LLM. Ollama и облачный API — альтернативы. В mock
этих вызовов нет. В `run_audit` маркеры вычисляются сразу после детекторов, до
маскирования; правила используют уже найденные маркеры после смысловых проверок.
Классификатор работает локально без API-ключа; если модели нет, шаг пропускается
с предупреждением. Найденные им особые категории маскируются до первого вызова LLM.

После `run_audit` worker создаёт копию и повторным извлечением проверяет, не остались
ли в ней найденные исходные значения ПДн. Если копия не прошла самопроверку или
создать её не удалось, отчёт сохраняется без неё (`redacted_available=false`).
Удаление исходника выполняется в `finally`, в том числе при ошибке проверки.

## Путь документа

```mermaid
sequenceDiagram
    autonumber
    participant B as Браузер (React)
    participant A as FastAPI
    participant D as PostgreSQL
    participant R as Redis
    participant W as Celery worker
    B->>A: POST /api/documents (файл, purpose, llm_mode, batch_id?)
    A->>A: Сохранить исходник в uploads
    A->>D: Создать документ и задачу queued
    A->>R: process_document(task_id)
    A-->>B: 202 TaskCreated {task_id, document_id}
    R->>W: Получить задачу
    W->>D: processing, этап и прогресс
    loop Пока queued или processing
        B->>A: GET /api/tasks/{task_id}
        A->>D: Прочитать статус
        A-->>B: TaskInfo {status, stage, progress}
    end
    W->>W: Извлечение, run_audit, копия и самопроверка
    W->>D: Подготовить отчёт, текст с маской, журнал и копию
    W->>W: Удалить исходник (finally)
    W->>D: Зафиксировать done, progress=100, report_id
    B->>A: GET /api/tasks/{task_id}
    A-->>B: TaskInfo {status: done, report_id}
    B->>A: GET /api/reports/{report_id}
    A->>D: Прочитать результат
    A-->>B: Report: светофор, чек-лист, нарушения, audit
    B->>A: GET /api/reports/{report_id}/text
    A-->>B: ReportText с масками для подсветки
```

Для ввода текста используется `POST /api/queries` с `QueryRequest`; дальше путь тот
же. При ошибке задача получает `failed` и понятное сообщение `error`; исходник
также удаляется. Цитаты и подсветка сохраняют координаты исходного текста.

## Сканы и изображения

PDF без текстового слоя и изображения PNG, JPG/JPEG, TIF/TIFF распознаются
Tesseract (`rus+eng`) в Celery worker, без внешнего OCR-сервиса. В многостраничном
TIFF каждый кадр — страница. В смешанном PDF сохраняется чтение текстового слоя,
а крупные изображения с недостаточным текстовым слоем распознаются отдельно:
до четырёх областей на страницу. Предел `OCR_MAX_PAGES=100` относится к операциям
распознавания (страница или область изображения), проверяется до запуска OCR.
PDF рендерится с `OCR_DPI=300`; увеличение dpi не восстанавливает детали плохого скана.

`ExtractedDocument.ocr` переносится в `Report.ocr`: движок, уверенность по страницам,
средняя уверенность и неуверенные отрезки в общих координатах текста. Пороги по
умолчанию: слово < 0,6 (`OCR_LOW_WORD_CONF`), страница < 0,75 (`OCR_LOW_PAGE_CONF`).
Интерфейс показывает предупреждение и пунктир, чтобы пользователь сверил находки
с исходником. Уверенность OCR не является метрикой полноты детекции ПДн.
Распознанный текст проходит те же детекторы и маскирование перед LLM.

Обезличивание сканов реализовано в T-072: пиксели под найденными ПДн заменяются,
скан-страницы PDF пересобираются из новых изображений без исходных картинок.
Копия повторно проверяется; при ошибке или более 20 OCR-страницах документ получает
`redacted_available=false`. Это ограничение создания копии, а не проверки документа.
Пропущенные при распознавании или детекции ПДн могут сохраниться, поэтому нужен
визуальный контроль подготовленной копии.

## Комплект документов

`POST /api/batches` создаёт запись комплекта с необязательным названием и назначением.
Файлы загружаются последовательно отдельными `POST /api/documents` с `batch_id`,
`purpose` и `llm_mode`; каждый получает собственную задачу Celery и отчёт.
Лимит по умолчанию — 20 документов (`BATCH_MAX_DOCUMENTS`, настройка сервера).
Общей задачи очереди с приоритетами пока нет.

`GET /api/batches/{id}` вычисляет `BatchSummary` при чтении из БД, без повторной
проверки или вызова LLM. Общий цвет — худший среди готовых отчётов; если готовых нет,
он `null`. `complete=true` означает, что нет `queued`/`processing`, и допускает ошибки:
их отражают `documents_failed` и `documents[].error`. Нарушения группируются по правилу,
сначала красные, затем жёлтые, внутри уровня — по числу затронутых документов.
Значения ПДн и цитаты в сводку не включаются; название задаёт пользователь,
имена файлов проходят обработку для безопасного отображения.

Страница `/batches/{id}` опрашивает сводку каждые 2 секунды до завершения и сохраняется
при обновлении браузера; история хранит ссылку локально. Выгрузка
`GET /api/batches/{id}/export?format=pdf|md|json` возвращает текущий снимок сводки.
Отчёты и копии документов скачиваются отдельно. После удаления документов по сроку
хранения пустой комплект также удаляется; пустой новый комплект сохраняется до
истечения срока хранения.

## Выбор режима нейросети

`GET /api/llm/modes` возвращает режим по умолчанию и доступность `mock`, `local`,
`cloud`, без ключей API. `mock` доступен всегда. Для `local` проверяются Ollama
и наличие модели, для `cloud` — наличие адреса, ключа и модели в конфигурации;
проверочный запрос облачному провайдеру не делается. Доступность кэшируется на 10 секунд.
Недоступный режим серый в интерфейсе с причиной; запрос с таким `llm_mode` получает 400.

Выбранный режим хранится у документа и передаётся worker; `audit.llm_mode` фиксирует
режим проверки. Если режим не передан, используется `LLM_DEFAULT_MODE`, а при его
отсутствии или пустом значении — прежние `LLM_PROVIDER`/`LLM_BASE_URL`.
`LLM_LOCAL_*` и `LLM_CLOUD_*` настраивают провайдеров независимо; старые переменные
заполняют незаданные параметры соответствующего режима. Подробности совместимости
и настройки — в [README](../README.md#режимы-нейросети).

## Модули сервисов

Пути указаны относительно корня репозитория.

| Модуль | Папка или файл | Что делает |
|---|---|---|
| Конвейер | `backend/app/services/pipeline.py` | Порядок детекции, маскирования и проверок; собирает `AuditInfo`, `Report`, `ReportText` и журнал LLM |
| Извлечение | `backend/app/services/extraction/` | PDF — PyMuPDF, DOCX — python-docx, XLSX — openpyxl, XML — defusedxml; сканы — Tesseract; текст, страницы, разделы, смещения и уверенность OCR |
| Детекция | `backend/app/services/detection/` | Регулярки, контрольные суммы, Natasha NER и словари; локальный классификатор `grif-cls` для КТ и особых категорий |
| Маркеры | `backend/app/services/markers/` | Находит согласования, грифы, сроки хранения, согласие, поручение обработки и упоминания КИИ |
| Маскирование | `backend/app/services/masking/` | Плейсхолдеры для LLM, карта смещений и маска с сохранением длины для отчёта |
| Нейросеть | `backend/app/services/llm/` | Провайдер, бюджет, кэш Redis, поиск особых категорий и КТ, условия `llm`, проверка цитат и журнал вызовов |
| Правила | `backend/app/services/rules/` | Загружает YAML, хранит редактируемые правила в БД, проверяет условия и формирует нарушения со ссылками на регламенты |
| Отчёт | `backend/app/services/report/` | Светофор, ровно три категории чек-листа, цитаты и рекомендации; сводка комплекта и экспорт PDF / MD / JSON |
| Обезличенная копия | `backend/app/services/redaction/` | Физическое удаление найденных ПДн в PDF, замены в DOCX/XLSX/TXT/XML, замена пикселей сканов, самопроверка копии |
| Файлы | `backend/app/services/storage.py` | Временное сохранение исходников и их удаление |
| Сроки хранения | `backend/app/services/retention.py` | Удаляет просроченные отчёты вместе с копиями и связанными записями |
| Тексты законов | `data/legal/*.md`, `frontend/src/components/legalArticles.ts` | Статья открывается по клику из нарушения; смысловой поиск по законам (RAG) не делали — ссылка задаётся в правиле |

## Развёртывание и хранение

`docker-compose.yml` поднимает `frontend` (React, nginx, порт 3000), `api` (FastAPI,
порт 8000), `worker`, `redis` и `postgres` (PostgreSQL 16; образ с pgvector — задел под поиск по законам). Профиль
`local-llm` дополнительно запускает Ollama без публикации порта 11434 на хосте.
Выбор моделей CPU/GPU и настройка NVIDIA — в [local-llm.md](local-llm.md#какую-модель-выбрать-t-029b).

API и worker используют общий том `uploads` для временных исходников.
Правила, тексты законов и локальный классификатор подключены из `data/rules`,
`data/legal` и `data/models` только для чтения. API читает метрики из `eval/results`.
В PostgreSQL сохраняются отчёт, текст с масками, журнал LLM и байты доступной копии;
Redis обслуживает очередь и кэш ответов LLM.

## Безопасность

- **Что видит нейросеть.** Только текст после маскирования найденных ПДн:
  `[PERSON_1]`, `[SNILS_1]` и другие плейсхолдеры. После поиска особых категорий
  новые ПДн маскируются повторно до поиска КТ и условий правил. Точный отправленный
  фрагмент доступен в отчёте «Что видела нейросеть» и через
  `GET /api/reports/{report_id}/llm-log` (`LlmCall.masked_fragment`). Карта
  `MaskResult.mapping` остаётся в памяти, не сохраняется и не логируется.
  Коммерческая тайна и финансы не маскируются: в облачном режиме этот контекст
  получает провайдер. Пропущенные детектором ПДн могут остаться в тексте — граница
  защиты зависит от полноты детекции.
- **Проверка доказательств.** Код засчитывает цитату LLM только при дословном
  совпадении с отправленным текстом. Для условия `llm` ответ `yes` без найденной
  цитаты понижается до `unknown`. Наличие цитаты подтверждает источник текста,
  но не гарантирует правильность смысловой оценки модели.
- **Защита от подмены инструкций.** В проверке условий правил документ отделён
  от инструкций разделителями с меткой из первых 12 hex SHA-256 фрагмента;
  последовательности `<<<` и `>>>` внутри заменяются безопасными символами.
  Документ трактуется как данные. Разделители и проверка цитаты снижают риск
  подмены инструкций, но не дают абсолютной гарантии поведения модели.
- **Исходники и копии.** После проверки исходник удаляется, в том числе при ошибке.
  Копия создаётся до удаления и выдаётся только после самопроверки. В PDF применяется
  физическая редакция текста; на сканах — замена пикселей, в DOCX/XLSX/TXT/XML — замены. КТ и финансовые сведения
  в копии сохраняются. Текст отчёта маскируется с сохранением длины (`█`), поэтому
  его смещения совпадают с исходным текстом; это другой вид маски, чем для LLM.
- **Сроки хранения.** Отчёты и обезличенные копии хранятся `REPORT_TTL_DAYS`
  (по умолчанию 7 дней), затем удаляются периодической задачей Celery. Кэш ответов
  LLM в Redis имеет отдельный срок 7 дней. `AuditInfo` фиксирует хэш документа,
  версии правил, словарей и приложения, детекторы, провайдера, модель и число
  реальных обращений к LLM без значений ПДн.
- **Логи и ключи.** В технические логи пишутся идентификаторы, этапы, время и
  счётчики, без значений ПДн. API-ключи хранятся только в локальном `.env`,
  который не входит в репозиторий. В mock ключ не требуется; Ollama использует
  заглушку. Для CPU задаётся `LLM_TIMEOUT_S=120`: это таймаут сетевой операции,
  а не всей проверки документа.
