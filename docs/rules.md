# Каталог правил проверки

Человекочитаемое описание правил из `data/rules/rules.yaml`. Ведёт **Алина**.
Каждое правило здесь = одна запись в YAML с тем же ID (формат условий — `docs/contracts.md`, раздел 2).

Уровень: **red** — серьёзное нарушение, документ нельзя отправлять как есть;
**yellow** — замечание, стоит исправить.

| ID | Название | Закон и статья | Уровень | Когда срабатывает | Рекомендация |
|---|---|---|---|---|---|
| `PD_IN_PUBLICATION` | Персональные данные в документе для публикации | 152-ФЗ, ст. 7; ст. 10.1 | red | Назначение «для публикации» и найдена хотя бы одна сущность категорий `pd` / `pd_special` | Удалите или обезличьте ПДн перед публикацией либо получите согласие на распространение |
| `TRADE_SECRET_WITHOUT_MARK` | Коммерческая тайна без грифа | 98-ФЗ, ст. 10 | red | Найдены сведения категории `trade_secret` и нет маркера `classification_mark` | Нанесите гриф «Коммерческая тайна» с указанием обладателя информации |
| `…` | | | | | |

## Как добавить правило

1. Добавьте строку в таблицу выше.
2. Добавьте запись в `data/rules/rules.yaml` с тем же ID.
3. Запустите `cd backend && pytest tests/test_schemas.py` — правило должно пройти валидацию.
