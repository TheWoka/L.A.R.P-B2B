# T-015a — экспорт отчёта в JSON и удаление отчётов по сроку хранения

Дата: 21.10.2026. Ветка: `feat/T-015a-export-ttl`, создана от обновлённого `main` (`f8837c5`).

## Что сделано

- `GET /api/reports/{report_id}/export?format=json` возвращает сохранённый Report как UTF-8 JSON: `ensure_ascii=False`, отступ 2, `Content-Type: application/json`.
- Заголовок скачивания: `Content-Disposition: attachment; filename="report_<report_id>.json"`. Исходное имя документа в имя скачиваемого файла не входит.
- Нет отчёта → 404 «Отчёт не найден». PDF → 501 «Будет реализовано в T-020». JSON также используется по умолчанию.
- `purge_expired(session, now=None)` удаляет отчёты с `created_at < now - REPORT_TTL_DAYS`, связанные задачи и документы, а также оставшиеся исходники из `stored_path`; возвращает число удалённых отчётов.
- Если у документа есть другой действующий отчёт, документ сохраняется, чтобы не удалить этот отчёт каскадом.
- Добавлена задача `app.worker.tasks.purge_expired_reports` с собственной сессией БД; Celery beat вызывает её раз в 3600 секунд. Worker запускается с `-B`.
- В журнал очистки записывается только количество: `purged_reports=N`.

## Отклонения и ограничения

- По последующему прямому указанию пользователя Git выполняется через консоль; исходное требование GitHub Desktop заменено этим указанием.
- Этот файл добавлен сверх исходного списка файлов по отдельному запросу пользователя на отчёт. `docs/planning/` не затронут.
- Ручная проверка Swagger, длительный запуск beat и перезапуск всего стенда в этой проверке не выполнялись; места для результатов оставлены выше.
- Очистка периодическая: после истечения TTL отчёт удаляется при следующем успешном запуске задачи, обычно в пределах часа при работающем worker/beat.
- Срок берётся из settings.report_ttl_days; config.py и модель БД не менялись. Отчёт ровно на границе TTL сохраняется до следующей проверки.
- PDF остаётся отдельной задачей T-020. Удаление будущих обезличенных копий T-026 не реализовано: в текущей модели нет пути к ним.
- Удаление файла и транзакция БД не атомарны: при сбое commit файл уже может быть удалён; повторное удаление отсутствующего файла безопасно.
- Тест экспорта подтверждает отсутствие исходного ФИО в проверенном текстовом сценарии; поле Report.filename сохраняет исходную семантику контракта. Безопасное имя вложения не означает обезличивание любых произвольных имён внутри Report.

## Объяснение для защиты

Сервис аудита сам создаёт отчёты, которые тоже нужно хранить ограниченное время: в них остаются сведения о документе, нарушениях, коммерческой тайне и финансах. Маскирование найденных ПДн уменьшает риск, но не делает бессрочное хранение безопасным. Поэтому система удаляет свои отчёты по настраиваемому TTL, а связанные записи и оставшиеся исходники очищает вместе с ними. Так она применяет принцип ограниченного хранения к собственным данным, а пользователь при необходимости заранее скачивает отчёт в JSON.
