# Демо-набор ИИ-аудитора — T-017a

Шесть коротких документов закупки для жюри и видео. Все люди, организации и реквизиты
придуманы; документы помечены как учебные. Личный телефон имеет код 999, общие контакты
используют example.ru/example.org. Линия 8-800 в документе 06 — специально заданная
ловушка, а не личный телефон. Банковские реквизиты и карты в набор не включены.

## Воспроизведение

Из корня репозитория, PowerShell, **по одной команде**. Docker Desktop должен работать,
в локальном `.env` нужен `LLM_PROVIDER=mock`. Кириллическое имя папки требует явного
имени Compose-проекта; для существующего стенда используйте его имя.

```powershell
$env:COMPOSE_PROJECT_NAME = 'ai-auditor'
docker-compose build api
docker-compose run --rm --no-deps -v "${PWD}/data:/data_rw" api python /data_rw/demo/make_demo.py --out /data_rw/demo
docker-compose up --build -d
```

Откройте <http://localhost:3000>, выберите файл и назначение из таблицы ниже,
нажмите «Проверить документ» и дождитесь отчёта. Перед отправкой проверьте выбранное
назначение: по умолчанию форма выбирает публикацию.

Проверки генератора после сборки:

```powershell
docker-compose run --rm --no-deps -v "${PWD}/data:/data_rw" api python /data_rw/demo/make_demo.py --self-test
docker-compose run --rm --no-deps -v "${PWD}/data:/data_rw" api ruff check /data_rw/demo/make_demo.py
```

Генератор пересоздаёт только шесть известных имён, сохраняя ключ, README и другие файлы.
Перед генерацией закройте документы в Word/Excel. Seed 1701 даёт одинаковые выдуманные
СНИЛС и ИНН с валидными контрольными суммами через функции
`backend/app/evaluation/generator/values.py`. Повторяется содержимое, а не бинарные
временные метки ZIP/PDF.

### Расхождения и наблюдения

- **04, извлечение и детектор.** Строки `Смета!A6:C6` и `Смета!A7:C7` превращаются
  в `Себестоимость единицы | 48300 | руб.` и `Наценка | 0.25 | %`: разделители
  отделяют числа от единиц, а формат 25% теряется. Вероятная причина — сочетание
  `services/extraction/xlsx.py` (сырые значения) и `services/detection/dict_detector.py`
  (шаблон суммы/процента); правило не срабатывает без сущности, ожидание red сохраняется.
- **02, детектор маркера.** Видимая строка `Конфиденциально. ООО «Пример Закупки»…`
  не распознана: `_is_classification` в `services/markers/find_markers.py` принимает
  отдельную короткую плашку, колонтитул или некоторые фразы заглавными. Это пропуск
  маркера; green соответствует каталогу, поскольку `CHECKLIST_NO_MARK` действует только для internal.
- **01, пояснения чек-листа.** При нарушении «Коммерческая тайна без грифа»
  чек-лист одновременно сообщает «Гриф не требуется». В `services/report/builder.py`
  publication исключено из требования грифа; для жюри это неоднозначность пояснений,
  итог red и ключ не меняются.
- **05, чек-лист шире правил.** Чек-лист требует гриф и срок хранения для
  SPECIAL_CATEGORY, хотя правила `CHECKLIST_NO_MARK`/`CHECKLIST_NO_RETENTION`
  используют паспорт, СНИЛС, ИНН и дату рождения. Дополнительных нарушений нет;
  это различие чек-листа и каталога, а не пропуск red-правила.

Код backend/frontend, словари и правила при разборе расхождений не исправлялись.

## Проверки и отклонения окружения

- 7 встроенных тестов прошли, ruff — без замечаний. Проверены форматы, повторная
  генерация и сохранность ключа, неверный путь, пустые страницы, переполнение PDF,
  контрольные суммы и арифметика сметы. PDF проверен после рендера PyMuPDF,
  XLSX — после импорта и рендера Artifact Tool, DOCX — в установленном Word.
- `render_docx.py` запущен, но LibreOffice отсутствует (`soffice.exe` не найден).
  Для DOCX использован просмотр Word; автоматический рендер DOCX в PNG не подтверждён.
- Первой командой был обязательный `docker-compose build api`. Потребовались явное
  имя проекта и запуск Docker Desktop, затем pip упал с ReadTimeout от
  `files.pythonhosted.org`. Обычный `docker-compose up --build -d` также попробован
  и завершился ошибкой BuildKit EOF.
- Прогон завершён с **временным Compose override вне репозитория**: API/worker
  используют `FROM ai-auditor-api:latest` и копирование текущего backend.
  Версии всех 16 закреплённых зависимостей образа совпали с `requirements.txt`,
  frontend собран обычным Dockerfile. **Чистая стандартная сборка не подтверждена.**
- Использован существующий проект `larp-b2b-main` с портами 3000/8000. Старая БД
  вернула 500 (`documents.stored_path` отсутствует); для демо создан отдельный том
  `larp-b2b-main_demo_t017a_pgdata`, прежний том сохранён. API/worker перезапущены
  для создания схемы; миграции и код не менялись.
- Из-за нехватки памяти временный worker ограничен `--concurrency=1`.
  Измеренные 114–144 мс — время конвейера, не время HTTP-загрузки и не нагрузочный тест.
