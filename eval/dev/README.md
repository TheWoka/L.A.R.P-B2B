# Набор для настройки детектора (T-033)

Автор: Codex, по заданию команды проекта «Гриф».
Дата: 2026-10-24.

Это открытый разработчикам набор для настройки коммерческой тайны и особых
категорий ПДн: по нему можно разбирать ошибки и изменять детектор, словари
и промпты. Он не заменяет независимую оценку качества. В отличие от `eval/dev`,
слепой набор `eval/blind` нельзя просматривать или использовать для настройки.
Документы этого набора написаны независимо, без просмотра blind, seed,
реализации детектора и словаря проекта.

В наборе 15 файлов `.txt`, по 13–16 строк: письма поставщикам, чат менеджеров,
калькуляция, служебная записка, протокол переговоров, коммерческое предложение,
план продаж, технологическая памятка, отчёт о закупке, кадровая справка,
журнал больничных, характеристика, анкета и закрытые условия поставщика.
Последний документ содержит отрицательные примеры КТ и особых категорий ПДн.

Всего размечено 55 фрагментов `TRADE_SECRET` и 20 `SPECIAL_CATEGORY`.
Также представлены все десять обычных типов ПДн и 11 фрагментов `FINANCIAL`.

Все люди, ФИО, компании, обстоятельства, адреса, номера и суммы вымышлены.
Домены используются только `example.ru` и `example.org`; банк — АО «Банк Пример»,
БИК 049999999. Телефоны и идентификаторы — синтетические примеры, а не контакты
и не платёжные реквизиты. Звонить или переводить средства по ним не следует.
Технологические описания также придуманы для разметки.

Разметка — `[[TYPE:значение]]`, без вложений и переноса метки между строками.
У `TRADE_SECRET` выделены содержание закрытого условия или показатель со
значением, без пояснения после него. У `SPECIAL_CATEGORY` — факт о конкретном
человеке; после поля с двоеточием выделено только значение. ФИО размечены
отдельно как `PERSON`, внутри других меток они не встречаются.
Личные контакты размечены, общие ящики организаций оставлены без меток.

Для T-033 по прямому условию задачи суммы открытых контрактов и НМЦК размечены
как `FINANCIAL`, хотя общий `eval/README.md` перечисляет их среди ловушек без
разметки. Публичные цены, НДС, учебный пример налога на прибыль, БИК, паспорт
изделия, член закупочной комиссии и медицинская закупка без конкретного человека
не размечены как КТ или особые категории. Расчётные счета организаций размечены
как `FINANCIAL`, личный счёт — как `BANK_ACCOUNT`.

Проверка из корня репозитория (PowerShell), сначала сборка:

```powershell
docker-compose build api
docker-compose run --rm --no-deps -v "${PWD}/eval:/eval:ro" -v "${PWD}/eval/results:/out:rw" api python /eval/run_eval.py --corpus /eval/dev --out /out/dev
```

Отдельный том `/out` позволяет сохранить результат в `eval/results/dev`, когда
`/eval/results` у сервиса API подключён только для чтения. Результаты оценки
не входят в этот набор и не коммитятся. Прогон без `--llm` не вызывает LLM;
низкая метрика не означает ошибку разметки и не служит поводом менять эталон
под текущее поведение детектора.
