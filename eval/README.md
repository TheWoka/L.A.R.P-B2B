# Оценка качества детекции (T-014a)

Скрипт считает precision, recall и F1 по каждому типу сущностей и два критерия приёмки
хакатона: **recall ПДн ≥ 0.90** и **recall коммерческой тайны ≥ 0.85**. Результат —
`eval/results/metrics.json` по схеме `Metrics` (`docs/contracts.md`, раздел 1); его покажет
страница «Качество проверки» (T-028).

Логика — в `backend/app/evaluation/` (так тесты идут и в Docker), `run_eval.py` — тонкая обёртка.

## Запуск

Локально (Python 3.11, зависимости backend):

```bash
cd backend
python ../eval/run_eval.py --corpus ../eval/seed --out ../eval/results
```

В Docker (PowerShell, из корня репозитория; `eval/` монтируется в контейнер):

```powershell
docker-compose run --rm --no-deps -v "${PWD}/eval:/eval" api python /eval/run_eval.py --corpus /eval/seed --out /eval/results
```

### Классификатор по умолчанию, `--no-model` — без него (T-036b)

По умолчанию детектор тот же, что в конвейере без ключа: `detect` (regex, NER, словари) →
`mask` → классификатор `grif-cls` (`backend/app/services/detection/model_detector.py`, модель —
`data/models/grif-cls`, CPU, без сети и ключа). Поэтому страница «Качество проверки» показывает
реальную систему. Классификатор находит коммерческую тайну и особые категории ПДн «по смыслу»;
особая категория засчитывается, только если рядом есть человек (ст. 10 152-ФЗ).
Модели нет — шаг пропускается с предупреждением, счёт идёт как раньше.

`--no-model` — только regex, NER и словари, для сравнения «до/после»; в `metrics.json`
поле `corpus` получает суффикс « (без классификатора)».

```powershell
docker-compose run --rm --no-deps -v "${PWD}/eval:/eval" -v "${PWD}/eval/results:/out" api python /eval/run_eval.py --corpus /eval/dev --out /out/dev
docker-compose run --rm --no-deps -v "${PWD}/eval:/eval" -v "${PWD}/eval/results:/out" api python /eval/run_eval.py --corpus /eval/dev --out /out/dev-no-model --no-model
```

Флаг `--strict` — код выхода 1, если не выполнен хотя бы один критерий (для CI).
Код 2 — ошибка в корпусе (неизвестный тип, вложенная разметка, нет пары `.json` и т.п.)
или `--llm` без настроенной нейросети.

### Флаг `--llm` — особые категории ПДн и коммерческая тайна нейросетью (T-013e, T-013d)

С флагом к обычной детекции добавляются те же шаги и в том же порядке, что в конвейере:
`detect` → `mask` → классификатор (без него при `--no-model`) → `detect_special_llm` (особые категории ПДн, ст. 10 152-ФЗ) → если что-то
найдено, `mask` заново (находка — ПДн, дальше её не видит ни один вызов) →
`detect_trade_secrets_llm`. Особые категории: в LLM уходят только строки с привязкой к
человеку (`[PERSON_n]` рядом, «работник», «он» …), до 2 пакетов на документ
(`backend/app/services/llm/special_category.py`).
Нейросеть видит только замаскированные строки-кандидаты и предлагает цитаты; находка засчитывается, только если цитата дословно есть в тексте (подробно —
`backend/app/services/llm/trade_secret.py`). Лимит — `LLM_MAX_CALLS_PER_DOC` на документ.

```powershell
docker-compose up -d redis
docker-compose run --rm -v "${PWD}/eval:/eval" -v "${PWD}/eval/results:/out" api python /eval/run_eval.py --corpus /eval/seed --out /out/seed-llm --llm
```

- `metrics.json` получает `corpus` с суффиксом « + LLM» (`seed + LLM`), чтобы страница
  «Качество проверки» не путала прогон с обычным.
- В конце печатается число реальных запросов к LLM (попадания в кэш Redis не считаются).

> ⚠️ **Нужен ключ в `.env`** (`LLM_PROVIDER=openai_compatible`, `LLM_BASE_URL`, `LLM_API_KEY`,
> `LLM_MODEL`). Без него скрипт завершится с кодом 2 и ничего не посчитает.
> **Вызовы платные:** до 5 запросов на документ — до 2 на особые категории и до 3 на КТ
> (на `eval/seed` по расчёту отбора кандидатов — 26 + 21 = 47 запросов на 31 документ).
> Повторный прогон того же корпуса идёт из кэша Redis бесплатно — если Redis запущен
> (`docker-compose up -d redis`); с `--no-deps` без Redis кэша нет и каждый прогон платный.
> **`eval/blind`** прогоняется с `--llm` один раз, в самом конце; настраивать промпт по нему нельзя.

## Результаты (`eval/results/`, не коммитятся)

| Файл | Что внутри |
|---|---|
| `metrics.json` | `Metrics.model_dump(mode="json")`: `corpus` — имя папки, `documents`, `by_type`, `pd_recall`, `trade_secret_recall`, `matching` |
| `errors.json` | пропуски (`missed`) и лишние находки (`extra`): `{file, kind, type, start, end, context}` |

`context` — ±30 символов вокруг сущности, сама сущность в `⟦ ⟧`. **В контексте замаскированы
все ПДн — и эталонные, и найденные детектором** (категории `pd`, `pd_special`; объединение
отрезков, `mask_preserving_length`). Так значение не утечёт, даже если его забыли разметить.
Цена: лишние находки ПДн (например, `info@` организации) в `errors.json` тоже видны только
в маске — разбирать их удобнее по `start`/`end` в исходном документе.

## Как считается

- **Совпадение:** тот же `type` и пересечение отрезков ≥ 50% длины **эталонной** сущности.
  Сопоставление один к одному, жадно по убыванию пересечения: одна находка закрывает не больше
  одного эталона. Находка правильного места, но другого типа — это пропуск + лишняя находка.
- **По типу:** precision = tp / (tp + fp), recall = tp / (tp + fn), F1, `support` = число эталонов.
  Нет находок → precision 1.0; нет эталонов → recall 1.0. Типы без эталона и без находок не выводятся.
- **`pd_recall`** — микро-recall по всем сущностям категорий `pd` и `pd_special`;
  **`trade_secret_recall`** — по `trade_secret`. `FINANCIAL` выводится, но в критерии не входит.

## Формат корпуса

В одной папке можно смешивать два формата.

**1. Разметка в тексте** (`*.txt`, стартовый набор `eval/seed/`):

```
Представитель: [[PERSON:Иванов Иван Петрович]], тел. [[PHONE:+7 912 345-67-89]]
```

Парсер убирает `[[TYPE:` и `]]`, координаты сущностей — в чистом тексте. Категория берётся из типа:
`pd` — PERSON, PASSPORT, SNILS, INN, PHONE, EMAIL, ADDRESS, BIRTH_DATE, CARD, BANK_ACCOUNT;
`pd_special` — SPECIAL_CATEGORY; `trade_secret` — TRADE_SECRET; `financial` — FINANCIAL.
Разметка не переходит на другую строку. Вложенная разметка, неизвестный тип, пустое значение
или незакрытая скобка → ошибка с именем файла и номером строки.

**2. Файл + JSON** (генератор Алины, T-011): `name.docx|pdf|xlsx|txt` и рядом `name.json`:

```json
{"purpose": "contract", "entities": [{"type": "PERSON", "category": "pd", "start": 120, "end": 140}]}
```

Координаты — в `ExtractedDocument.text`, который вернёт `extract()`; для `.txt` текст — один
сегмент, как в worker. Если рядом с `name.txt` лежит `name.json`, разметка в тексте не ищется.

## Как размечать (правила для `eval/seed/` и T-011)

Размечаем как аудитор, а не под текущий детектор: метрика должна показывать реальные пропуски.

| Тип | Что входит в отрезок |
|---|---|
| PERSON | ФИО в любой форме и падеже: «Иванов Иван Петрович», «Иванову И.П.», «И.П. Иванов», «ИВАНОВ», латиница с карты |
| PASSPORT | серия и номер: «45 06 № 123456», «4506 123456». Кем и когда выдан, код подразделения — не входят |
| SNILS, INN, CARD | номер целиком. INN — только 12 цифр (физлицо, ИП) |
| PHONE, EMAIL | личные контакты физлица. Общие линии и ящики организации (8-800, приёмная, info@, zakupki@) — **не размечаем** |
| ADDRESS | адрес физлица (регистрация, проживание, ИП) от индекса/города до квартиры. Адрес организации — не размечаем |
| BIRTH_DATE | только дата. Даты договоров, выдачи паспорта, согласования — не размечаем |
| BANK_ACCOUNT | счёт физлица или ИП (40817…, 40802…) |
| SPECIAL_CATEGORY | сведения о здоровье, убеждениях и т.п. (ст. 10 152-ФЗ) — фраза со значением до конца фразы. После метки с двоеточием — только значение: «Национальность: [[русский]]», «по медицинским показаниям: [[астма]]». Требование «отсутствие судимости» — не размечаем |
| TRADE_SECRET | показатель + значение: «Себестоимость … 48 300 руб.», «наценка 14%», «индивидуальные скидки 12%». Пояснения после значения не включаем |
| FINANCIAL | показатель + значение («Выручка за 2025 год — 412,6 млн руб.») и расчётный счёт организации (40702…) |

**Ловушки — не размечаем:** ИНН юрлица (10 цифр), КПП, ОГРН/ОГРНИП, БИК, ИКЗ, номер извещения
и контракта, НМЦК, цена и обеспечение контракта, «НДС 20%», «налог на прибыль 20%», «паспорт
изделия», «серия поставки», слово «себестоимость» или «перечень клиентов» без самого значения.

Только выдуманные данные: репозиторий публичный (AGENTS.md, правило 2).
