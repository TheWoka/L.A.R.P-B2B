# Генератор синтетического корпуса — T-011b

Генератор использует только `random.Random(seed)`, собственные списки значений и уже
установленные библиотеки backend. Faker и новые зависимости не нужны. Все сведения
выдуманы; адреса содержат вымышленные города, почта использует `example.invalid`.
Совпадение синтетических ФИО или числовых идентификаторов с реальными случайно.

## Запуск

Из корня репозитория, с зависимостями backend:

```powershell
python eval/generator/generate.py --out eval/corpus --count 210 --seed 42
python eval/run_eval.py --corpus eval/corpus --out eval/results
```

В Docker, PowerShell, из корня (настройка `.env` — как в основном README):

```powershell
docker-compose build api
docker-compose run --rm --no-deps api ruff check .
docker-compose run --rm --no-deps api pytest -q
docker-compose run --rm --no-deps -v "${PWD}/eval:/eval" api python /eval/generator/generate.py --out /eval/corpus --count 210 --seed 42
docker-compose run --rm --no-deps -v "${PWD}/eval:/eval" api python /eval/run_eval.py --corpus /eval/corpus --out /eval/results
```

Параметры по умолчанию: `--out eval/corpus --count 210 --seed 42`.
Количество должно быть положительным. Шаблоны чередуются по кругу: число документов
каждого шаблона отличается не более чем на один. Результат пишется в пустую папку;
для повторного запуска выберите новый `--out` или самостоятельно очистите прежний корпус.
Генератор не удаляет существующий корпус и не смешивает разные запуски.

## Шаблоны и объём

| Шаблон | Формат | purpose | Документов при count=210 |
|---|---|---|---:|
| contract — стороны и подписанты договора | DOCX | contract | 30 |
| application — заявка с паспортом и СНИЛС | DOCX | contract | 30 |
| questionnaire — анкета заглавными | DOCX | internal | 30 |
| offer — коммерческое предложение | DOCX / PDF попеременно | publication | 30 |
| specification — ТЗ без ПДн с ловушками | DOCX | publication | 30 |
| estimate — смета с контактным лицом | XLSX | internal | 30 |
| international — контракт на русском и английском | TXT | international | 30 |

Каждый DOCX содержит абзацы и одну таблицу. Маркеры согласования, коммерческой тайны,
срока хранения и согласия независимо включаются или пропускаются по seed.
В конце выводятся только количества документов по форматам и шаблонам, сущностей
по типам и общее количество. Значения в консоль и логи не выводятся.
Корпус из 210 документов содержит 1830 сущностей, в том числе 300 TRADE_SECRET.

## Разметка и совместимость с T-014a

Каждый документ сопровождается одноимённым JSON:

```json
{"purpose": "contract", "entities": [{"type": "PERSON", "category": "pd", "start": 120, "end": 140}]}
```

`read_for_markup(path)` использует тот же способ чтения, что загрузчик T-014a:
для TXT — `text_document()` из `app.evaluation.corpus`, для DOCX/PDF/XLSX — `extract()`.
После записи значения последовательно ищутся в полном извлечённом тексте, от конца
предыдущей сущности. Координаты — индексы символов `[start, end)`. Изменений контракта,
загрузчика корпуса и сервисов извлечения или детекции нет.

Категории берутся из `CATEGORY_BY_TYPE` T-014a. Размечаются только ПДн и коммерческая
тайна. У паспорта вводное слово «серия» остаётся вне отрезка; серия, знак № и номер
входят в него по правилам `eval/README.md`. TRADE_SECRET — вся фраза с показателем
и значением. Фразы о здоровье имеют категорию `pd_special`.

Ловушки не размечаются: ИНН/КПП юрлица, ОГРН, счёт 40702…, ИКЗ, номер контракта,
НМЦК, налог на прибыль, паспорт изделия и серия поставки. Счета физлиц начинаются
с 40817 и имеют контрольный ключ для синтетического БИК 049999999. СНИЛС, ИНН и
карты проверяются существующими валидаторами.

## PDF и воспроизводимость

PDF записывается через PyMuPDF `page.insert_htmlbox`, с кириллическим шрифтом MuPDF.
Строки располагаются последовательно на широких страницах, чтобы исключить
переносы внутри размечаемого значения. После записи проверяется точное извлечение
всех значений, включая кириллицу. При несовпадении генерация завершается ошибкой
с именем шаблона и типом сущности, без самого значения; незавершённая пара удаляется.

Если окружение не поддерживает обратное извлечение кириллицы, явно отключите PDF:

```powershell
python eval/generator/generate.py --out eval/corpus-no-pdf --count 210 --seed 42 --no-pdf
```

Все коммерческие предложения тогда будут DOCX; статистика сообщает об отключении PDF.
Одинаковый seed даёт побайтово одинаковые JSON при одинаковых версиях библиотек.
Бинарные DOCX/XLSX/PDF могут содержать служебные временные метки; их побайтовая
идентичность не гарантируется. Документы и результаты оценки не коммитятся.
